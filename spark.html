로컬 LLM 길잡이 · DGX Spark 편

작성 기준일 2026년 11월 13일 · 마지막 수정 2026년 11월 19일 · 모델·버전·가격·보안 정보는 작성 기준일 당시 내용이고(11월 18~19일에 일부를 추가로 확인), 이후 바뀌었을 수 있습니다.

「로컬 LLM 길잡이」에서 DGX Spark의 설치와 운영 부분만 따로 떼어 낸 파일입니다. Spark에서 직접 LLM을 돌리는 방법과, 내 데스크톱에서 Spark를 부리고 관리하는 방법을 다룹니다. DGX Spark가 무엇이고 몇 대가 필요한지는 본편 11장에 있습니다.

저작권: 이 파일은 「로컬 LLM 길잡이」의 일부입니다. 저작권과 출처는 본편 14장에 정리했습니다. 명령은 NVIDIA 공식 플레이북을 보고 옮겨 줄인 것이고, 판 고정(sed 줄, 주소 속 긴 커밋 번호)은 이 문서가 덧붙였습니다. 일부 운영 팁은 커뮤니티 사용 후기에서 알게 된 것입니다.

Spark에서 직접 LLM 돌리기 (1대 · 2대 · 4대)

Spark에 모니터·키보드를 꽂고 그 자리에서 쓰는 방식입니다. Spark는 우분투 기반 DGX OS에 Docker가 미리 깔려 나오므로, 대부분 컨테이너 하나 띄우기로 끝납니다. 컨테이너는 프로그램을 필요한 부품째 한 상자에 담아 다른 프로그램과 섞이지 않게 돌리는 방식입니다. 아래 명령은 Spark 화면에서 연 터미널(명령창)이나 2장의 SSH 창에 붙여 넣습니다.

이 장을 읽으면 Spark 1대·2대·4대에서 컨테이너로 모델을 띄우는 순서와, 대수마다 무엇을 바꾸는지 알게 됩니다.

따라 하기 전에: 그대로 쓰는 값과 바꿔 쓰는 값

이 문서의 명령에 나오는 주소·이름은 특정 회사나 개인의 실제 값이 아닌 공통 예시입니다. 명령 안에서는 아래처럼 구분해 표시했고 명령마다 바로 밑에 무엇을 바꾸는지 적었습니다.

이렇게 내 값으로: 장비·계정마다 달라 확인하고 맞추는 값 이렇게 바꿔도 됨: 그대로 써도 되고 필요하면 바꾸는 값 표시 없음 그대로 복사
  • $로 시작하는 이름($USER, $VLLM_IMAGE 등)은 자동으로 채워지거나 앞 줄에서 정한 값을 불러오는 것이라 그대로 둡니다.
  • # 뒤는 설명(주석)이라 같이 복사돼도 실행에 영향이 없습니다.
  • 줄 끝의 \는 "다음 줄과 이어짐"이라는 뜻입니다. Spark(리눅스) 명령창에는 그대로 붙여 넣고 Windows PowerShell에서는 한 줄로 이어 붙입니다.
  • 포트 번호를 바꾸면 그 번호로 접속하는 주소(localhost:번호)도 같이 바꿉니다.

목표: Spark 한 대에서 gpt-oss-120b 같은 120B급 MoE 모델을 대화 화면으로 쓰기. 쉬운 길(Ollama + Open WebUI)과 여럿이 동시에 쓰거나 API로 붙이는 길(vLLM) 두 가지입니다. 혼자 쓸 때는 Ollama로도 충분히 빠릅니다(본편 11장의 llama.cpp 측정 참고, Ollama는 조금 다를 수 있음).

방법 A. Ollama + Open WebUI (가장 쉬움)

  1. Docker를 매번 sudo(관리자 권한 실행) 없이 쓰도록 권한 주기 
    sudo usermod -aG docker $USER
newgrp docker
docker ps     # 오류 없이 빈 목록이 나오면 OK

    전부 그대로. $USER는 지금 로그인한 사용자 이름으로 자동으로 채워집니다.

  2. 대화 화면과 Ollama가 함께 든 컨테이너 실행. 127.0.0.1:을 붙여 Spark 안에서만 열고 내 PC에서는 2장의 SSH 터널(내 PC와 Spark 사이에 여는 암호화된 접속 통로)로 들어갑니다. 
    docker run -d -p 127.0.0.1:8080:8080 --gpus=all \
  -v open-webui:/app/backend/data \
  -v open-webui-ollama:/root/.ollama \
  --name open-webui ghcr.io/open-webui/open-webui:ollama

    8080 Spark 쪽 포트. 다른 프로그램과 겹치면 다른 번호로 바꾸고 접속 주소도 같이 바꿉니다(뒤쪽 :8080은 컨테이너 안 번호라 그대로) · open-webui 컨테이너 이름

  3. Spark의 브라우저에서 http://localhost:8080 접속 → 관리자 계정 만들기 → 모델 검색칸에 gpt-oss:120b 입력해 내려받기 → 대화 시작

방법 B. vLLM (여러 명이 동시에 쓰거나 API로 붙일 때)

export HF_TOKEN="허깅페이스_토큰"           # huggingface.co/settings/tokens
export VLLM_IMAGE=nvcr.io/nvidia/vllm:26.10-py3   # 2026-11 기준 최신. 새 태그는 NGC에서 확인
# 127.0.0.1: Spark 안에서만 열기 · -v: 받은 모델을 Spark 디스크에 보관
docker run -d --gpus all -p 127.0.0.1:8000:8000 --name vllm-server \
  -e HF_TOKEN="$HF_TOKEN" \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  $VLLM_IMAGE vllm serve openai/gpt-oss-120b --gpu-memory-utilization 0.7

# 준비됐는지 확인 (처음에는 60GB 넘게 내려받아 100Mbps면 1시간 반쯤, 기가 인터넷이면 10~20분. 두 번째부터는 몇 분. 진행은 docker logs -f vllm-server)
curl http://localhost:8000/health
curl http://localhost:8000/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-oss-120b","messages":[{"role":"user","content":"안녕"}]}'

허깅페이스_토큰 내 토큰(huggingface.co → Settings → Access Tokens에서 Read 권한으로 발급) · 26.10-py3 NGC에 올라온 최신 태그로. 26.10은 vLLM 0.31.0 기반이라 2026년 10월 말 취약점 수정 전 판이니 127.0.0.1에만 열어 두고 새 태그가 나오면 올립니다(본편 부록 2). 새 태그(vLLM 0.34 이상)는 메모리 비율 기본값이 100%라 2대·4대 명령에도 --gpu-memory-utilization 0.7~0.8을 넣으세요 · 0.7 메모리의 몇 할을 쓸지. 릴리스 노트는 Spark 같은 통합 메모리 장비에서 메모리 부족 오류가 나면 0.7처럼 낮추라고 안내합니다 · curl …/health는 준비되면 아무 글자 없이 끝나고 Connection refused, Connection reset by peer, Empty reply from server 같은 오류가 나오면 아직 로딩 중입니다(진행 상황은 docker logs -f vllm-server) · 8000 바꾸면 아래 curl 주소도 같이 · openai/gpt-oss-120b 다른 모델의 허깅페이스 이름으로(curl의 model 값도 같게) · vllm-server 컨테이너 이름 · 안녕 시험 질문 · $HF_TOKEN $VLLM_IMAGE는 첫 두 줄에서 정한 값을 불러오는 것이라 그대로

이렇게 띄운 http://localhost:8000/v1은 Open WebUI·코딩 도우미 등 어떤 앱에도 붙일 수 있습니다(본편 8장 3층 구조). 코딩 도우미·에이전트가 도구를 쓰게 하려면 모델에 맞는 옵션을 덧붙입니다(gpt-oss는 --enable-auto-tool-choice --tool-call-parser openai).

두 가지 길: ① 권장: 내 PC의 NVIDIA Sync Cluster Assistant로 두 대를 묶은 뒤, 2026년 10월판 플레이북 「Serve LLMs with vLLM Across DGX Sparks」로 띄웁니다(이 탭 맨 아래 「2026년 10월에 나온 방법」). ② 대안: 아래의 Ray 방식(2026년 6월판 플레이북, NVIDIA 공식 이미지만 사용)입니다. 네트워크 설정은 둘 중 한 방법으로만 합니다.

목표: 두 대를 케이블로 묶어 한 대에 안 들어가는 모델(예: Llama 3.3 70B 원본, 235B급 MoE)을 나눠 싣기. 405B INT4는 공식 예시에서도 겨우 올라가는 수준입니다. NVIDIA 공식 플레이북 「vLLM」(2026-06-12판)의 Ray 방식 순서 그대로입니다. 이 판은 9월 개편 때 build.nvidia.com에서 빠져 지금은 NVIDIA GitHub 저장소에만 남아 있습니다. Cluster Assistant로 이미 묶었다면 아래 IP 고정·SSH 단계는 건너뜁니다(네트워크 설정을 두 방법으로 겹쳐 하면 설정 파일이 충돌합니다). 예시의 Llama 3.3 70B 원본은 Dense라 두 대에서도 초당 3~5토큰 안팎으로 느립니다(대역폭으로 계산한 어림값). 실제로 쓰기보다 연결 확인용으로 보세요.

  1. 두 대 모두 같은 사용자 이름으로 로그인 (whoami로 확인).
  2. QSFP 케이블 연결 후, 살아 있는 포트 확인. 두 대 모두 같은 번호 포트를 쓰세요. 
    ibdev2netdev
# ... enp1s0f1np1 (Up)  ← (Up)인 이름을 기억
    user@spark-1:~$ ibdev2netdev roceP2p1s0f0 port 1 ==> enP2p1s0f0np0 (Down) roceP2p1s0f1 port 1 ==> enP2p1s0f1np1 (Up) rocep1s0f0 port 1 ==> enp1s0f0np0 (Down) rocep1s0f1 port 1 ==> enp1s0f1np1 (Up)

    그대로. 결과에서 (Up)으로 나온 이름이 다음 단계들의 enp1s0f1np1 자리에 들어갑니다.

  3. 전용 망 IP 고정 (1번 Spark 예시. 2번은 끝자리를 .11로) 
    # 주소는 NVIDIA 공식 예시(전용 망용 사설 주소). 바꿀 땐 모든 Spark를 같은 대역으로
sudo tee /etc/netplan/40-cx7.yaml > /dev/null <<EOF
network:
  version: 2
  ethernets:
    enp1s0f1np1:
      addresses: [192.168.100.10/24]
      dhcp4: no
    enP2p1s0f1np1:
      addresses: [192.168.101.10/24]
      dhcp4: no
EOF
sudo chmod 600 /etc/netplan/40-cx7.yaml
sudo netplan apply

    enp1s0f1np1 enP2p1s0f1np1 2단계 결과의 이름(같으면 그대로) · 192.168.100.10 192.168.101.10 1번 Spark는 그대로, 2번은 끝자리를 .11로(4대면 .12 .13) · /24와 나머지 줄은 그대로

  4. 비밀번호 없는 SSH 설정: NVIDIA 「Connect Two Sparks」 플레이북의 assets/discover-sparks 스크립트를 한 대에서 실행 (또는 각 Spark에서 ssh-keygen -t ed25519로 키를 만든 뒤 ssh-copy-id 사용자@상대 주소로 서로 키 등록). 확인: 1번에서 ssh 192.168.100.11 hostname을 쳐서 비밀번호를 묻지 않고 2번 Spark의 이름이 나오면 OK
  5. 두 대 모두 vLLM 이미지와 클러스터 스크립트 준비 
    docker pull nvcr.io/nvidia/vllm:26.05-py3
wget https://raw.githubusercontent.com/vllm-project/vllm/51c1ee9b7c8acbba4899a8ebffd390685d171946/examples/ray_serving/run_cluster.sh
# 이 이미지에는 ray가 없어서, 시작할 때 설치하도록 한 줄 고침
sed -i 's|^RAY_START_CMD="ray start|RAY_START_CMD="pip install -q --root-user-action=ignore '\''ray[default]>=2.9'\'' \&\& ray start|' run_cluster.sh
chmod +x run_cluster.sh

    26.05-py3 플레이북이 검증한 판이라 클러스터는 이 태그로 고정합니다(1대 탭의 26.10과 다름). 26.10으로 올리면 ray 포함 여부와 메모리 설정을 다시 확인하세요. 두 대 모두 같은 태그로 · 긴 주소 속 영문·숫자(51c1ee9b…)는 검증된 판을 고정한 것이고, sed 줄도 그대로 · ray는 컨테이너를 시작할 때마다 새로 받으므로(인터넷 필요), 한 대만 다시 시작하면 판이 어긋나 합류가 거부될 수 있습니다. 처음 설치된 판을 pip show ray로 확인해 두고 판을 맞춰야 할 때는 sed 줄의 >=2.9를 ==그 판 번호로 바꿔 고정하세요. 그럴 땐 모든 Spark의 컨테이너를 같이 다시 시작하세요

docker exec -it $VLLM_CONTAINER /bin/bash -c '

연결 속도가 200Gbps가 아니라 26Gbps 수준으로 나오면 ConnectX-7 네트워크 칩 펌웨어 문제일 수 있습니다(한 사용 사례에서 펌웨어 업데이트로 해결, 아래 Dataiku). 두 대 모두 DGX Dashboard의 업데이트(네트워크 칩 펌웨어 포함)를 실행하거나 아래 명령으로 같은 일을 합니다. 케이블을 꽂기 전에 두 대 모두 미리 업데이트해 두면 겪지 않습니다. 펌웨어 업데이트 뒤에는 재부팅하고 도중에 전원을 끄지 마세요. 
sudo apt update

그대로. 두 대 모두에서 실행합니다.

2026년 10월에 나온 방법: NVIDIA는 2026년 10월(22일 갱신) 새 2대 플레이북 「Serve LLMs with vLLM Across DGX Sparks」를 냈습니다. eugr가 관리하고 NVIDIA 플레이북이 채택한 이미지(eugr/spark-vllm-b12x, 태그는 고정하고 출처를 확인하세요)와 모델별 설정 파일(레시피)로 띄우는 방식입니다. 예시 모델은 Qwen3.8 Flash-Next(64GB 판 2대)와 GLM-5.3-Flash(128GB 판 2대)입니다. 클릭으로 하려면 2장의 Sync Model Launcher가 가장 쉽습니다. 이 탭의 방식은 NVIDIA 공식 이미지만 쓰는 대신 단계가 깁니다. 새 방식은 Ray를 쓰지 않고 ① NVIDIA Sync Cluster Assistant(또는 「Connect Multiple DGX Sparks」의 setup-cluster.sh)로 두 대를 잇고 ② 커뮤니티 런처(eugr/spark-vllm-docker)의 레시피로 띄웁니다. 64GB 판과 128GB 판은 한 클러스터로 묶지 않습니다(모두 64GB이거나 모두 128GB).

목표: 네 대(512GB)로 두 대에 안 들어가는 큰 MoE 올리기. NVIDIA 플레이북 「vLLM」 6월판(지금은 GitHub에만 있음)의 4대 예시는 MiniMax M2.5(229B. 회사가 처음부터 8비트(FP8) 위주로 내놓아 원본이 약 230GB)입니다. 4비트로 줄인 모델이면 600~700B급(본편 11장 표)까지 노려볼 수 있습니다. 2대와 순서는 같고 케이블 대신 스위치가 들어가고 워커가 3대가 됩니다.

  1. 준비물: Spark마다 200Gbps 이더넷 연결을 하나씩 줄 수 있는 관리형 스위치(400Gbps 포트는 200Gbps 둘로 나눠 써도 됨), Spark당 QSFP112 DAC 케이블 1개(NVIDIA 승인 목록 참고), 네 대 모두 최신 OS·펌웨어(DGX Dashboard 업데이트). Spark와 이어진 포트를 모두 같은 네트워크(브리지나 VLAN)로 묶고 MTU는 기본값 그대로 둡니다(스위치 설명서 참고).
  2. 속도 확인: 자동 협상으로 200Gbps가 안 잡힐 수 있어, 네 대 모두 확인합니다. 느리게 잡히면 케이블·포트 모드·자동 협상·FEC 설정을 점검합니다. 
    sudo ethtool enp1s0f1np1 | grep Speed    # Speed: 200000Mb/s 여야 함

    enp1s0f1np1 각 Spark에서 (Up)인 이름

  3. 네트워크·SSH 설정: 내 PC의 NVIDIA Sync Cluster Assistant로 진행하는 것이 지금 공식 권장입니다(4대는 스위치 필요). 명령으로 하려면 NVIDIA 「Connect Multiple DGX Sparks」 플레이북의 Configure Manually 탭대로 setup-cluster.sh를 씁니다(--topology switch --mtu 1500). 이전 판(GitHub)의 spark_cluster_setup 스크립트나, 2대 탭 3단계의 IP 고정을 네 대에 .10 / .11 / .12 / .13으로 반복하는 방법도 됩니다. 어느 방법이든 아래 단계의 헤드 주소(예시 192.168.100.10)는 실제로 정해진 1번 Spark의 전용 망 주소로 바꿉니다.
  4. 1번 헤드 + 2~4번 워커: 네 대 모두 2대 탭의 5단계(이미지·run_cluster.sh 준비)를 먼저 하고 1번은 6단계(헤드), 2~4번은 7단계(워커)대로 띄웁니다. 새로 시작한다면 2대 탭 5단계와 같은 26.05-py3·고정 스크립트 조합으로 네 대를 맞추는 것을 권합니다(더 새 판이고 2대 탭과 같아 맞추기 쉬움). 다만 NVIDIA가 4대로 검증한 조합은 이전 판 예시인 26.02-py3와 버전을 고정하지 않은 run_cluster.sh입니다. 어느 쪽을 쓰든 6·7단계의 태그를 같게 해서 네 대 모두 같은 태그로 맞춥니다. 워커 세 대에서 각각 --worker로 헤드(192.168.100.10)에 합류합니다.
  5. 모델 내려받기: 네 대 모두 각자의 컨테이너 안에서 받습니다. 
    export VLLM_CONTAINER=$(docker ps --format '{{.Names}}' | grep -E '^node-[0-9]+$')
docker exec -it $VLLM_CONTAINER /bin/bash -c '
  hf auth login
  hf download MiniMaxAI/MiniMax-M2.5'

    MiniMaxAI/MiniMax-M2.5 다른 모델이면 그 이름으로(다음 단계도 같게)

  6. 모델 띄우기 (1번에서): 네 조각으로 나눕니다. 
    export VLLM_CONTAINER=$(docker ps --format '{{.Names}}' | grep -E '^node-[0-9]+$')
docker exec $VLLM_CONTAINER ray status    # GPU 4개 확인
docker exec -it $VLLM_CONTAINER /bin/bash -c '
  vllm serve MiniMaxAI/MiniMax-M2.5 \
    --tensor-parallel-size 4 --max-model-len 129000 --max-num-seqs 4 \
    --trust-remote-code --host 127.0.0.1'

    129000 컨텍스트 길이(메모리 부족 오류가 나면 줄이거나 --gpu-memory-utilization 0.8을 덧붙임. 명령에 이 옵션이 빠진 것은 공식 4대 예시를 그대로 따른 것이고, 빠져 있으면 vLLM 기본값으로 동작) · 4 동시에 처리할 요청 수 · --tensor-parallel-size 4와 --trust-remote-code는 그대로

대수를 늘리면 담을 수 있는 크기는 확실히 늘지만 속도가 대수만큼 빨라지지는 않습니다(본편 11장). 큰 모델 하나 대신 네 대에 각각 다른 모델(대화용·코딩용·문서 검색용·실험용)을 1대 탭 방식으로 따로 띄우는 것도 좋은 운영법입니다. 2026년 10월에 나온 「vLLM Across DGX Sparks」 플레이북은 명령 예시가 2대뿐이고, 3~4대는 Sync(Cluster Assistant와 Model Launcher)로 하는 길만 안내합니다. 네트워크만 묶으려면 「Connect Multiple DGX Sparks」의 Configure Manually 탭에 3~4대를 명령으로 묶는 방법도 나와 있습니다. 3대는 스위치 없이 케이블 3개로 고리처럼 이을 수 있고(NVIDIA 3대 연결 안내), Cluster Assistant는 스위치 없이 3대까지, 스위치를 쓰면 4대까지 지원합니다(NVIDIA는 앞으로 나올 Sync 판에서 8대를 지원하겠다고 밝혔고 2026-11-13 현재는 4대까지입니다).
02

내 데스크톱에서 Spark를 부리고 관리하기

Spark는 책상 옆이나 서버실에 두고 평소 쓰는 Windows 데스크톱에서 접속해 쓰는 방식입니다. 모니터를 Spark에 따로 꽂을 필요가 없어서 실제로는 이쪽이 더 흔합니다.

이 장을 읽으면 평소 쓰는 Windows PC에서 Spark에 접속해 모델을 쓰고 관리하는 방법을 알게 됩니다.

방법 A. NVIDIA Sync 앱 (클릭으로)

Sync는 내 PC에 까는 연결 관리 앱입니다. SSH 터널을 대신 열어 주고 Spark 쪽 앱을 클릭으로 띄웁니다. 아래는 2026년 11월 기준 0.148판입니다.

  1. 내 PC에 NVIDIA Sync(Windows용 .exe)를 설치합니다. 사용권에 동의하면, 내 PC에 깔린 편집기(VS Code·Cursor 등) 가운데 Sync로 열 것을 고르는 창이 나옵니다.
  2. Spark를 추가합니다. 같은 네트워크면 spark-abcd.local 같은 이름으로 자동 검색되고 회사망처럼 검색이 안 되면 Settings → Devices → Add New → Add a device manually에서 Spark의 IP 주소, 사용자 이름, 비밀번호를 넣습니다. Sync는 이 비밀번호로 한 번만 들어가 키 방식 SSH를 설정해 두고 그 뒤로는 비밀번호 없이 접속합니다.
  3. 작업 표시줄의 Sync 아이콘 → Spark 선택 → Connect. 아래 같은 창이 뜹니다.
  1. DGX Dashboard를 누르고 Spark 사용자 이름·비밀번호로 로그인합니다.
  1. 모델을 클릭으로 띄우기 (Model Launcher, 베타): Sync의 Settings → Models에서 Spark를 고르고 Configure를 누르면 NVIDIA가 정해 둔 모델과 vLLM 컨테이너(커뮤니티 이미지 eugr/spark-vllm)를 받아 둡니다. 다 받으면 Start Model을 누르고 상태가 Running이 되면 Copy endpoint(작업 표시줄 창에서는 Copy model URL)로 주소를 복사해 코딩 도우미나 Open WebUI에 붙입니다. 2026년 11월 현재 Spark에서 고를 수 있는 모델은 Qwen3.8 27B NVFP4 하나이고, 1대에서도 2~4대 클러스터에서도 쓸 수 있습니다. 다른 모델은 1장처럼 직접 띄웁니다.
  1. Open WebUI처럼 직접 띄우는 앱은 Custom에 등록합니다. 이름, 포트, 시작 스크립트(docker run 명령)를 넣고 "Auto open in browser"를 켜 두면 클릭 한 번으로 컨테이너 시작, 터널, 브라우저 열기가 같이 됩니다. 공식 예시는 포트 12000(-p 12000:8080)이고, 이 문서 기준대로 Spark 안에서만 열려면 -p 127.0.0.1:12000:8080으로 씁니다. 주소는 http://localhost:12000입니다.
  2. 여러 대를 묶을 때는 Settings → Clusters의 Cluster Assistant가 네트워크·SSH 설정과 연결 점검을 대신해 줍니다(1장 2대 탭의 3~4단계, 4대 탭의 3단계).
  3. CPU·메모리·GPU 사용량 그래프는 Sync의 Resource Monitor로도 봅니다(1대·클러스터 모두).

방법 B. SSH 터널 직접 (명령 한 줄)

Windows에는 SSH가 기본으로 들어 있습니다. PowerShell에서:

ssh -L 8080:localhost:8080 -L 8000:localhost:8000 -L 11000:localhost:11000 user@spark-abcd.local

user Spark 사용자 이름 · spark-abcd Spark 이름(안 잡히면 .local까지 지우고 IP 주소) · 8080 8000 11000 내 PC 쪽 번호. 내 PC에서 이미 쓰는 번호면 바꾸고 브라우저 주소도 같이(명령 안에서 localhost: 뒤 번호는 Spark 쪽이라 그대로)

user와 spark-abcd는 자리 표시입니다. 내 Spark의 사용자 이름과 장치 이름으로 바꾸고 회사망처럼 .local 이름이 안 잡히면 Spark의 IP 주소를 대신 씁니다(주소 읽는 법). 처음 접속하면 이 컴퓨터를 믿겠느냐(yes/no)고 물으니 yes, 이어서 Spark 비밀번호를 넣습니다. 이 창을 닫으면 터널도 끊깁니다. 이 창을 열어 둔 동안 내 PC에서 이렇게 씁니다.

대화하기브라우저로 http://localhost:8080 (Spark의 Open WebUI)
코딩 도우미 연결VS Code의 Cline·Continue에서 Base URL http://localhost:8000/v1, API 키 none
상태 보기·업데이트브라우저로 http://localhost:11000 (DGX Dashboard)
클러스터 상태 보기위 명령에 -L 8265:localhost:8265를 더하고 http://localhost:8265 (Ray 대시보드)
살아 있는지 확인curl.exe http://localhost:8000/v1/models (모델 이름이 든 글이 나오면 정상)
Spark 명령 내리기같은 SSH 창에서 docker ps, nvidia-smi, 클러스터면 1장 2대 탭 8단계의 두 줄(컨테이너 이름을 찾는 export VLLM_CONTAINER=…, 이어서 ray status)

방법 C. 내 PC 그래픽카드와 Spark를 같이 쓰기 (하이브리드)

  1. 내 PC에 Ollama를 설치하고 작은 모델을 받습니다. 16GB 그래픽카드 기준 예시이고, 8GB면 더 작은 모델을 고릅니다. 
    ollama run gpt-oss:20b

    gpt-oss:20b 그래픽카드 메모리에 맞는 다른 모델로(Ollama 모델 목록, 본편 7장 조합기)

  2. SSH 터널을 엽니다. Spark에는 1장의 vLLM(1대 탭 방법 B, 또는 2대·4대 탭)이 떠 있어야 합니다. 이 방식은 Spark의 vLLM만 쓰므로 8000번만 엽니다. 
    ssh -L 8000:localhost:8000 user@spark-abcd.local

    user spark-abcd 방법 B와 같게 · 8000 바꾸면 4단계 주소의 8000도 같이

  3. 내 PC에 Docker Desktop을 설치합니다(설치 중 WSL2 설치와 재부팅이 필요할 수 있고 회사 규모에 따라 유료입니다: 본편 9장 회사 탭). 그다음 Open WebUI를 3000번으로 띄운 뒤, 브라우저로 http://localhost:3000에 들어갑니다. PowerShell에서는 줄바꿈 기호 \가 통하지 않으므로 한 줄로 붙여 넣습니다. 
    docker run -d -p 127.0.0.1:3000:8080 --add-host=host.docker.internal:host-gateway -v open-webui:/app/backend/data --name open-webui ghcr.io/open-webui/open-webui:main

    3000 내 PC 쪽 포트. 바꾸면 브라우저 주소도 같이 · open-webui 컨테이너 이름 · host.docker.internal과 :8080은 그대로

  4. Open WebUI 관리자 설정 → 연결에서 Ollama 칸에 http://host.docker.internal:11434, OpenAI API 칸에 http://host.docker.internal:8000/v1(키 none)를 둘 다 넣습니다. 이제 대화창 위 모델 목록에 두 곳의 모델이 함께 나옵니다.

관리할 때 기억할 것

  • 포트는 Spark 안에만: 엔진과 대시보드는 Spark 안(127.0.0.1)에만 열어 두고 내 PC에서는 SSH로만 들어갑니다(본편 9장 보안 수칙). 밖에서 쓰려면 공유기 포트포워딩 대신 Tailscale을 씁니다. NVIDIA Sync의 Settings → Tailscale에서 켤 수 있고 방법은 NVIDIA 「Connect to your Spark」 플레이북의 Enable Tailscale 탭에 있습니다. Tailscale을 켜도 이미 열린 포트가 닫히지는 않으니, 공유기 포트포워딩·DMZ가 없는지 함께 확인합니다(본편 9장 보안 수칙). 클러스터(Ray)를 띄웠다면 헤드에서 sudo ss -ltnp | grep -E "6379|8265"로 Ray 포트(6379, 대시보드 8265)가 어느 주소에 열렸는지 확인하고 전용 망(192.168.100.x)이 아닌 주소에도 열려 있으면 방화벽으로 그 대역만 허용합니다.
  • 업데이트는 대시보드에서: DGX Dashboard의 업데이트로 OS·드라이버·펌웨어를 함께 올립니다. 클러스터면 모든 Spark를 같은 버전으로 맞추세요.
  • 끊기지 않게: 클러스터 헤드·워커 명령과 모델 띄우기(vllm serve) 명령은 tmux 안에서 실행합니다. SSH가 끊기면 서버가 내려가거나 로그를 볼 수 없는 채로 남을 수 있기 때문입니다.
  • 모델 파일 위치: 내려받은 모델은 각 Spark의 ~/.cache/huggingface에 쌓입니다. 클러스터는 모든 Spark에 같은 모델이 있어야 하니 저장 공간을 미리 확인하세요.
  • 메모리가 남는데도 부족 오류가 나면: Spark는 CPU와 GPU가 메모리 하나를 나눠 쓰는 구조라, 아직 여기에 맞춰지지 않은 프로그램에서 생길 수 있습니다. NVIDIA 설명서에는 임시 방법으로 캐시 비우기가 나와 있습니다: sudo sh -c 'sync; echo 3 > /proc/sys/vm/drop_caches'를 실행한 뒤 프로그램을 다시 시작합니다.
  • 모니터 없이 쓰면 메모리를 조금 더: Spark는 화면용으로 메모리 2GB를 기본으로 잡아 둡니다. 모니터를 꽂지 않고 내 PC에서만 접속한다면, 재부팅 중 Esc(또는 Del)를 눌러 UEFI 설정에 들어가 Advanced → Advanced Menu → Display Reserved Memory를 Auto(모니터가 없으면 0.5GB)로 바꿔 약 1.5GB를 모델에 더 쓸 수 있습니다. 바꾸기 전후로 free -h의 total을 비교하세요(NVIDIA 설명서).

명령은 NVIDIA DGX Spark 공식 플레이북(Connect Two Sparks, Multi Sparks through Switch, vLLM, Open WebUI, Connect to your Spark)을 보고 옮겨 줄인 것입니다. Open WebUI·Sync·접속 방법은 build.nvidia.com 최신판과 대조했고(2026-11-13에 다시 보니 바뀐 것 없음), 1대 vLLM 명령은 이전 판의 형태에 26.10 릴리스 노트의 메모리 설정을 더한 것입니다. 2대·4대의 Ray 방식은 지금 NVIDIA GitHub 저장소에만 남은 이전 판(vLLM 6월 12일판, Connect Two Sparks·Multi Sparks through Switch)을 따랐습니다. Sync 화면과 Model Launcher는 NVIDIA Sync 사용자 설명서(0.148판), 대시보드는 DGX Spark 사용자 설명서, 연결 화면은 Open WebUI 문서를 보고 단순화해 다시 그렸습니다. 포트를 127.0.0.1에만 여는 설정과 모델 보관용 -v는 본편 9장 보안 수칙에 맞추려고 이 문서에서 덧붙였습니다. 컨테이너 태그(26.05-py3 등)와 인터페이스 이름은 장비마다 다를 수 있으니 실제 작업 때는 NVIDIA 공식 플레이북을 함께 보세요. 링크 속도 26Gbps 문제는 Dataiku 사례 참고.
